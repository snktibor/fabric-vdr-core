This is the cross-tool premise ledger for the frozen bridge. The exact copied [v4 contracts](inputs/contracts-v4.json), [clause catalog](inputs/jml-clause-catalog.json) and [37-case evidence inventory](inputs/jml-case-coverage.json) identify every clause below. Clause IDs use R for `requires`, E for `ensures`, A for `assignable`, S for `signals` and O for `signals_only`, numbered in each case. The catalog retains the full clause text, so these references do not depend on shortened quotations.

None of the Java clauses is proved by this Lean artifact. The named `PerCallContracts` premise is a cross-tool Hoare/runtime premise. It is allowed to be supplied by externally checked Java proofs, provided their exact contract hashes, adapter environment, proof dependency closure and runtime transfer match. At the recorded inspection there were 37 v4 cases, seven with a matching JML-hash report saying `PROVED_AND_FRESHLY_REPLAYED`, and 30 without such evidence. Those seven reports were inspected, not independently replayed or certified here. The per-case JSON is authoritative; older or different-contract successful reports do not discharge v4 clauses. The Java agent may improve this independently.

The public exception partition is tracked case by case in the inventory. Creation has invalid input, missing parent, unauthorized and duplicate cases. Plain update has invalid input, missing entry, missing parent, unauthorized and negative/exhausted version cases. Guarded update adds invalid parser, first absent nonself guard, first mismatch self/nonself, and overflow after all guards match. Earlier guard success is required for a first-failure case. External adapter faults, erased-return type errors, unsupported String values, allocation failure, reflection or concurrent heap mutation are outside this partition unless the runtime boundary separately addresses them. Sufficient-case proofs plus this list are not, by themselves, a machine-checked exhaustiveness theorem.

The source supports the narrower signer-domain premise. [JwtValidator.authenticate](inputs/source/JwtValidator.java) obtains `issuerDid` through `requireText` at line 104 and returns it in `JwtPrincipal` at line 121. `requireText` at line 411 calls `JsonUtil.trimToNull` and rejects null. [JsonUtil.trimToNull](inputs/source/JsonUtil.java) at line 151 applies Java `trim()` and rejects the empty result. [VdrContract.requireSignerDid](inputs/source/VdrContract.java) at line 576 passes the resulting principal's signer to the entry service. Therefore the inspected real caller supplies a trimmed nonempty issuer, conditional on that caller/JVM/model binding. This is source evidence, not a newly proved JWT-caller theorem or a DID-grammar theorem.

The same [JWT source](inputs/source/JwtValidator.java) reads the DID at line 107, checks nonce existence at line 184, and buffers the nonce write at line 190 before the service runs. [BaseRegistry](inputs/source/BaseRegistry.java) implements get/exists via `getStringState` and captures the serialized String before `putStringState`. These explain the chosen observation/write schema. They do not prove decoding, stable snapshot, MVCC, nonce rollback or actual deployment semantics. Independent read-list grouping in `capturedExtras` is sufficient because validation is conjunction over keys; it is not a claim about physical cross-registry call order.

The guarded event clauses now include payload keys (S9.E12, likewise S7.E11/S8.E12). Events and return DTOs are not represented as commit verdicts by this bridge. The full target image is represented and proved exact; event delivery and a general event-schema theorem are outside the frozen safety targets.
