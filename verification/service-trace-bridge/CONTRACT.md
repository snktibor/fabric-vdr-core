Frozen bridge between service call observations and the existing atomic ledger

This lights-out task owns only this directory. The artifact consists of a separately frozen trace schema and exact proposition targets, proofs, witnesses, a relative fresh compiler replay and a complete axiom inventory. All dependency models remain unchanged. The chosen composition uses the already proved atomic ledger, rather than introducing another protocol. Normal service return is interpreted through named, externally checked Hoare clauses. The tradeoff is explicit cross-tool and runtime trust, with no claim that Lean executes or verifies Java or Fabric.

BridgeModel.lean and BridgeSpec.lean are sealed before proof search. Definition elaboration may precede sealing. Subsequent changes to these files require a new separately named amendment; proof failure never licenses silently changing a target. The source and dependency hashes identify the inspected Java v3/v4 contracts, immutable model copies and pinned Lean 4.23.0 runtime. The original first ledger endorsement target's known precedence defect remains preserved; this bridge imports the corrected proof chain, never claims the refuted target passed.

The normalized request has a mode, occurrence/effect ID, raw and normalized target and accumulator, signer, timestamp, ordered typed guards, and guarded/plain discriminator. Java trim removes characters with code unit at most 32 at either end. Lean String models only the losslessly decoded Java UTF-16 domain; the runtime/codec boundary must either establish that domain or extend the representation for unpaired surrogates. Normalized IDs and payloads have explicitly injective encodings. Entry and extra state are separate namespaces; parent encoding is injective within extras. Nonce keys must be separate from parent keys. Canonical Fabric composite keys, actual JSON/guard parser outputs, allowed key characters and valid compressed accumulator syntax remain codec premises. No parser or cryptographic verification is inferred from typed fields.

A trace contains immutable entry observations (requested String, optional full image and captured revision), parent observations, auth observations, immutable target write images, extra write keys, returned checked versions and a normal-return bit. The full image includes ID, accumulator, signed version, creation and update times. Mutation of Java DTOs after an observation cannot mutate these values. SnapshotRelation binds answer at each consumed ordinal to the proposal snapshot at THAT requested key, and separately binds every captured revision. It imposes no guard or counter success. Initial well-formed records and codec coherence distinguish absent bytes from JSON null/missing fields and version zero. Stored ID is metadata; writes use the requested key. Coherence of metadata with address, if used by an event/client, is a separate invariant.

For updates, the entry sequence is target followed by nonself guards in submission order; the parent sequence is the one normalized target. Guard i reuses target ordinal zero if self, otherwise ordinal 1 plus the number of earlier nonself guards. Checked output binds that immutable observation's old version and also equals the requested expected version. Target version is nonnegative and below MAX; image version is that captured version plus one, with exact accumulator replacement, old ID/creation preservation and transaction update time. Creation has no entry get, but its existence read becomes the single optional entry observation, proven absent by the codec/exists relation. Creation writes zero with normalized ID and both transaction times. Plain update has empty guards. Nonself guard parents are never in the service parent sequence.

The actual source order is target get, parent get/ownership, guard reads, put for updates, and parent get/ownership, exists, put for creation. Separate per-registry ghost sequences DO NOT prove cross-registry order. Safety uses only those sequences and the common snapshot. Source order is documented and is not an extra proof premise.

NormalPost fields expose every obligation. In particular no valid-transaction, eligibility, simulation or abstract-correctness axiom is admitted. PerCallContracts says that each normal-return occurrence meets the named external Java Hoare and adapter contract. It is NOT justified by reading normal-case requires as necessary conditions. The v4 public exceptional partition and typed/runtime domain must discharge necessity, or that part remains unproved. Exact clause coverage and verification status are recorded separately in JML-PREMISES.md. Rejected occurrences require no normal postcondition; permission is false or normal-return is false. All occurrences remain at their original indexes.

The raw commit interpreter only validates captured entry/extra revisions, normal return and permission, then installs immutable entry images and increments each distinct extra write revision once. It does not evaluate eligible. It is proved equal to Atomic.step using granular postconditions, snapshot relations and derived read coverage/write equality. Extra-only occurrences have no entry writes and explicitly capture/read/write their primary extra key; additional nonce/auth writes occur atomically in all modes. Extra values remain opaque in the ledger. AuthContract records DID presence, nonce absence, nonce write and namespace separation; JWT/owner/policy truth is external. A post-return event/serialization/caller failure must set platform permission false and discard all buffered writes, including nonce. In-memory rollback is not claimed.

The platform boundary uses a single ordered history, actual prefix snapshots no later than the occurrence, revision equality-preserving ranks with no ABA for represented keys, and whole-proposal atomic validation/rollback. The raw prefix equality and Origins transport are proved; actual deployed Fabric behavior and revision-rank correspondence are premises. All represented entry writers must use create-zero or checked successor. No deletion/reset/bypass writer is covered.

HonestCheck supplies a present record containing BOTH accumulator and version at the exact independent check prefix, a successful client check against that record, and present-record version pins for every guard at that same prefix. CheckFidelity interprets successful checks as nonrevocation in the persistent history. AuthenticatedFidelity ties intended effects to actual authenticated payload effects and supplies that check fidelity. The two checks need not share a prefix. Credentials and effect IDs retain their identities. Payload cryptography and signer authenticity remain explicit, and unchanged accumulator bytes are not silently interpreted as a revocation.

Exact targets are EligibilitySpec, WriteImageSpec, ReadCoverageSpec, CheckedProvenanceSpec, ValidationSpec, ApplySpec, StepSpec, RunSpec, CommitSpec, NoResetSpec, SafetySpec and EndToEndSpec. Additional lemmas may strengthen this inventory. Required nonvacuity covers heterogeneous guard versions, a selfguard reusing the pre-mutation target, creation, padded normalization and present accumulator/version provenance. Witnesses can be parameterized by the explicit injective codec boundary; that restriction must be reported. Replay uses fresh olean outputs and --trust=0, checks all frozen hashes and every named theorem's axioms. Custom axioms, placeholders and native_decide are prohibited. This is composition evidence, not original Argos reproduction or a verified Fabric implementation.
